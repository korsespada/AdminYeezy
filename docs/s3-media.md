# Медиа в S3

Все фото и видео каталога лежат в одном S3-бакете (`S3_BUCKET`) и отдаются через
`S3_PUBLIC_DOMAIN`. Папки ниже на самом деле префиксы ключей. Переносить
существующие файлы в новую структуру не нужно: их URL уже сохранены в Rails.

## Схема ключей

| Префикс | Что лежит | Кто пишет | Имя файла | Кто чистит |
|---|---|---|---|---|
| `batches/{batch_id}/` | Фото опубликованных товаров выгрузки (WebP) | `scripts/batch-workflow.js`, CSV-импорт | `{external_id}_{n}.webp`, после SEO-прогона `{slug-товара}-{slug-фото}.webp` | Публикация партии после SEO-прогона; удаление непушенной партии |
| `videos/` | Видео (MP4) и постер (WebP) | Публикация выгрузки, форма товара, «Видео» | `{sha256}.mp4` и `{sha256}-poster.webp` | `npm run media:gc` |
| `products/media/` | Ручные загрузки в карточке товара и очищенные фото David Studio | `lib/product-media-upload.ts`, `scripts/photo-clean-worker.mjs` | `{sha256 содержимого}.webp` | `npm run media:gc` |
| `photo-clean/{sha256}/` | Кропы «до/после» для проверки чистки | `scripts/photo-clean-worker.mjs` | `before.png`, `after.png` | не чистится |
| `supplier-media/david-studio/` | Зеркало фото поставщика | `scripts/mirror-david-studio-media.mjs` | `{sha256}.{ext}` | не чистится |
| `site/orders/` | Коллажи отзывов Chromoff | Chromoff-отзывы | `review-{hash}.webp` | не чистится |

Для видео из выгрузки `sha256` считается от ссылки источника, для загруженного
файла — от содержимого. Один ролик у нескольких товаров цветовой семьи
хранится один раз.

## Cache-Control

Заголовок выставляет `scripts/lib/s3-cache-control.js` (`cacheControlForKey`),
его используют все загрузки:

- `batches/` — `public, max-age=2592000` (30 дней). SEO-прогон может
  перекодировать фото по тому же ключу, поэтому без `immutable`.
- все остальные префиксы — `public, max-age=31536000, immutable`: имя файла
  содержит хеш и по этому ключу другое содержимое не появится.

Заголовок действует только для файлов, загруженных после изменения. У старых
объектов его нет, их кеширование по-прежнему зависит от настроек CDN.

## Уборка `videos/` и `products/media/`

У этих префиксов нет привязки к партии, поэтому файлы удалённых товаров и
несохранённые ручные загрузки остаются в бакете. Их убирает
`scripts/s3-media-gc.mjs` (`npm run media:gc`):

1. Получает ключи, на которые ссылается CRM:
   `GET /api/v1/admin/media_references` (роль owner или admin). Rails
   сканирует все текстовые и JSON-колонки, включая `product_media`,
   `products.video_url`, снимки `order_items.image_url_snapshot` и рассылки.
2. Сканирует все текстовые и JSON-колонки `yu_scraping`, кроме `analytics_*`:
   там ссылки ещё не опубликованных товаров и задания чистки фото.
3. Удаляет файл, только если на него нет ни одной ссылки и он старше
   `--min-age-days` (по умолчанию 30, минимум 7). Видео и постер
   сохраняются парой.

Запуск по умолчанию только печатает отчёт. Удаление — `--apply`. Если к
удалению больше половины старых файлов, скрипт останавливается до проверки
(`--force` снимает защиту). `--list` выводит полный список кандидатов.
Пустой ответ Rails отменяет удаление.

Нужные переменные: `S3_*`, `SCRAPING_DATABASE_URL`, `RAILS_API_URL` и
`RAILS_ADMIN_TOKEN` (или `RAILS_ADMIN_EMAIL` / `RAILS_ADMIN_PASSWORD`).
Эндпоинт должен быть развёрнут в Rails до первого запуска.
