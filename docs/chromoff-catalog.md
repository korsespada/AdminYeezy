# Каталог Chromoff

## Назначение

`/admin/chromoff` — раздел AdminYeezy для отдельной витрины Chromoff.
Chromoff остаётся самостоятельным магазином со своим меню, URL и SEO, но товар,
цена и фотографии хранятся в общем Rails-каталоге YeezyUnique. Отдельная
админка Chromoff для управления каталогом больше не требуется.

## Что хранится где

| Данные | Source of truth |
|---|---|
| Общий товар, цена, статус, медиа | Rails CRM `Product` / `ProductMedia` |
| Публикация на Chromoff, legacy slug, Chromoff SEO и режим синхронизации | Rails CRM `ChromoffListing` |
| Разделы и подкатегории Chromoff | Rails CRM `ChromoffCategory` |
| Старые данные Chromoff | Supabase, только read-only источник импорта |

Нельзя писать в Rails CRM напрямую через SQL. Все изменения выполняются через
Rails API и server actions AdminYeezy.

## Экран `/admin/chromoff`

В разделе есть:

- боковая панель фильтров в стиле основного каталога: название, описание, цена,
  поставщик, общая категория и подкатегория, пол, источник, AI-статус и
  публикация Chromoff; отдельно доступны раздел и подраздел Chromoff;
- карточки товаров в общем формате основного каталога с фотографиями,
  описанием, характеристиками, цветовыми вариантами, ценой и общими действиями;
- источник товара на каждой карточке: «Автосинхронизация» или «Ручной товар»;
- результат Chromoff AI-категоризации и отметка «проверить категорию»;
- состояние Chromoff SEO (`h1`, `seo_title`, `seo_description`) и поставщик-источник;
- полноценная форма общего товара с отдельной секцией Chromoff: публикация,
  категория, slug и Chromoff SEO;
- массовые действия основного каталога: категория, подкатегория, пол, цена,
  шаблон замеров и перенос в корзину;
- переключатель «Опубликовать на Chromoff» / «Скрыть с Chromoff»;
- модальное ручное добавление уже существующего товара в подкатегорию;
- модальное окно dry-run импорта и запуска импорта из прежнего Supabase-каталога.

Выбор корневого раздела включает его подкатегории. Фильтры и пагинация работают
через query-параметры URL, поэтому ссылкой на выборку можно поделиться.
На мобильной ширине фильтры открываются drawer-панелью, а редактор товара и
операционные действия используют полноэкранные/диалоговые окна.

## Публикация и SEO

`ChromoffListing.published` управляет видимостью только на Chromoff.
Он не меняет доступность или категорию товара на YeezyUnique. У listing есть
свои `legacy_slug`, `seo_title`, `seo_description` и `h1`; если override пустой,
используется значение общего товара.

Для импортированных в общий каталог товаров, которые должны существовать только
на Chromoff, используется `noindex` на YeezyUnique. Это не запрещает их
индексацию на Chromoff: у витрин разные маршруты и собственные SEO-поля.

## Автосинхронизация поставщиков

После успешного пуша товара в Rails API создаётся или обновляется
`ChromoffListing`, если поставщик входит в список `CHROMOFF_AUTO_SUPPLIER_IDS`.
Бренд товара на включение в режим Chromoff не влияет.

По умолчанию список состоит из трёх поставщиков:

```text
_Z4krSCEyDqn5hvTYMJDEp4rykS4WwC0I
_d_MrS1r4uCqp1cjuoVnfj6jJ42_p9R9NgeH-vag
_Z6wrSBWbbi48HUyk59lk5c4PXN9NKqUQ
```

Новое listing создаётся скрытым (`published=false`), чтобы оператор сначала
проверил категорию и SEO, затем нажал «Опубликовать на Chromoff». Уже
опубликованная карточка обновляет общий товар и сохраняет свою публикацию,
slug и SEO-overrides. Категория, назначенная вручную, не перезаписывается
следующим авто-пушем.

Ручные карточки и карточки от других поставщиков не перехватываются этой
синхронизацией: они остаются `sync_mode=manual` и видны в интерфейсе отдельно.

Во время AI-обработки разрешённого поставщика AdminYeezy передаёт AI отдельный
справочник активных Chromoff-категорий. AI возвращает ID категории в том же
ответе, где формирует название, описание и SEO; второго полного AI-прохода нет.
При confidence ниже `0.75` listing создаётся или обновляется скрытым с `needs_review`, а
оператор назначает категорию вручную в карточке `/admin/chromoff`.

## Импорт из старого Chromoff

Перед импортом в production-env AdminYeezy задать только на сервере:

```env
CHROMOFF_SUPABASE_URL=https://<project>.supabase.co
CHROMOFF_SUPABASE_SERVICE_ROLE_KEY=<service-role-key>
```

Для совместимости также поддерживаются исходные имена старого приложения:
`NEXT_PUBLIC_SUPABASE_URL` и `SUPABASE_SERVICE_ROLE_KEY`. Значения не должны
содержать лишних кавычек. Эти переменные нельзя добавлять в Git или передавать
в браузер.

Порядок работы оператора:

1. Нажать **«Проверить импорт»**. Это скачивает категории, подкатегории и товары
   из Supabase и выполняет Rails dry-run без записи.
2. Убедиться, что нет непривязанных категорий.
3. Нажать **«Импортировать каталог»** и дождаться сообщения о результате.
   Для полного каталога операция может занять несколько минут; страницу нельзя
   закрывать и нельзя нажимать кнопку повторно.
4. Проверить карточки, публикацию и нужные подкатегории в этом разделе.

Импорт идемпотентный: существующие Chromoff listings сохраняют свой статус
публикации. Новые позиции создаются как shared Rails products и связываются с
Chromoff-категориями. Данные заказов, корзин, Telegram-пользователей и история
старого Supabase в этот процесс не входят.

## Ошибки импорта

| Сообщение | Что проверить |
|---|---|
| `Нужны CHROMOFF_SUPABASE_*` | В production AdminYeezy нет обеих переменных. |
| `Не удалось прочитать categories ... HTTP 401/403` | URL относится к нужному Supabase-проекту, ключ — service role, без кавычек и пробелов. |
| `HTTP 404` | Неверный URL проекта или в источнике нет таблицы `categories`. |
| `Непривязанных категорий` | Добавить сопоставление в `lib/chromoff-source.ts`, затем повторить dry-run. |
| Сообщение долго не меняется | Импорт идёт пакетами до 200 товаров; дождаться завершения и не закрывать вкладку. |

## API

Админка использует:

```text
GET/PATCH /api/v1/admin/chromoff/categories
GET/POST/PATCH /api/v1/admin/chromoff/listings
POST /api/v1/admin/chromoff/imports
```

Публичная витрина читает только опубликованные позиции:

```text
GET /api/v1/catalog/chromoff/categories
GET /api/v1/catalog/chromoff/products
GET /api/v1/catalog/chromoff/products/:slug
```
