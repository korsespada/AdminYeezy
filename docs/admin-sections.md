# Разделы AdminYeezy

`AdminYeezy` - операционная админка на `https://admin.yeezyunique.ru`. Публичный storefront не содержит админский UI; `/admin` на сайте должен редиректить сюда.

## Главный экран

| URL | Назначение | Источники |
|---|---|---|
| `/` | Redirect по auth-состоянию | cookie `admin_token` / `/login` |
| `/login` | Вход через Rails admin auth | `POST /api/v1/admin/auth/login` |
| `/admin/home` | Launchpad со всеми разделами | Rails API, `yeezy_scraping` status |

Shell и главный экран поддерживают ширину от 360 px. Ниже 1024 px навигация
открывается отдельным доступным меню с ссылками на Home, товары, Chromoff,
выгрузки и CRM; logout остаётся отдельным control. Hero, status panel и
launchpad перестраиваются в одну колонку (на планшете допускается до двух
карточек), а от 1024 px сохраняется desktop navigation и grid. Статус Rails API
и scraping DB различает подключённый, недоступный и ненастроенный источник;
значения счётчиков без ответа показываются как `—`.

Production-доступ к `/admin/*` должен быть только по Rails JWT cookie `admin_token`. Локальные fallback-логины допустимы только в development.

## Каталог

| URL | Назначение | Режим |
|---|---|---|
| `/admin` | Опубликованные товары | Rails admin/products |
| `/admin/brands` | Бренды | Rails catalog lookups, read-only |
| `/admin/categories` | Категории и подкатегории | Rails catalog lookups, read-only |
| `/admin/chromoff` | Каталог Chromoff: общий формат карточек, 40/100/500 карточек на странице, bulk actions, массовая смена любого Rails-поставщика, фильтры по товару и Chromoff-статусам, отдельные поля публикации и SEO | Rails Chromoff API + Rails catalog lookups |
| `/admin/chromoff/categories` | Редактор разделов и подразделов Chromoff: название, slug, порядок, активность, сопоставление общей категории и добавление новых подразделов | Rails Chromoff API + Rails catalog lookups |
| `/admin/trash` | Архивированные товары | Rails admin/products |

Все изменения опубликованного каталога идут через Rails API. Прямые SQL-записи в Rails CRM Postgres запрещены.
В основной сетке выбор «Товаров на стр.» вынесен в шапку раздела, плотность
сетки карточек регулируется ползунком «В ряд» от 4 до 10 (запоминается в
браузере). Клик по чекбоксу карточки с Shift выделяет диапазон от предыдущей
выбранной карточки, как в выгрузках. В массовых действиях кнопка «В цветовую
семью» объединяет выбранные товары в новую именованную семью или добавляет их
в существующую: товарам присваивается общий `variant_group_key` через Rails
admin products PATCH. Кнопка корзины на карточке переносит товар в корзину
(`/admin/trash`), а не удаляет полностью.
В карточке товара основной сетки показываются основные данные, поставщик и цветовая
семья; даты публикации и сводка атрибутов из сетки скрыты. Счётчик
семьи отображается как компактный бейдж («2 варианта», «5 вариантов»), а полный
список цветовых вариантов — внутри формы товара; клик по варианту переключает
форму на соответствующую админскую карточку товара. Список загружается через
admin catalog endpoint, который возвращает цветовую семью вместе с товарами;
при открытии формы товар
дополнительно запрашивается через detail-endpoint, чтобы не зависеть от старого
кэша списка. При наведении на основную фотографию в сетке или таблице браузер
показывает её `alt_text` из media; если он ещё отсутствует, используется название
товара.

В открытой карточке товара отдельный предпросмотр «Рекомендации размера на
сайте» показывает таблицу поставщика по росту и весу. Она отделена от замеров
изделия и не используется для формирования размеров или вариантов товара;
редактор этой же таблицы остаётся доступен в характеристиках ниже.

Фото и видео товара в форме каталога можно добавить ссылкой или файлом. Фото
нормализуется в WebP, видео перекодируется FFmpeg в MP4 H.264/AAC (максимум
1080 px, `faststart`) с WebP-постером; готовые файлы попадают в собственный S3
по детерминированным ключам на основе содержимого. Ссылки на внешние CDN также
переносятся в S3. После нажатия «Сохранить» карточка закрывается сразу, а
медиа ставится в фоновую очередь отдельным запросом; очереди разных товаров
могут выполняться параллельно. Для видео остаётся отдельная кнопка ручного
переноса ссылки и доступен drag-and-drop файла в поле. Ошибка фоновой загрузки
не отменяет сохранение карточки и записывается в журнал сервера.

На ширине ниже 1024 px основной каталог показывает touch-friendly карточки,
открывает фильтры отдельным доступным drawer и использует полноэкранный sheet
для редактора товара. Таблица и сохранённое desktop-предпочтение остаются
доступны от 1024 px; mobile bulk actions переносятся в вертикальную панель без
глобального горизонтального overflow.

## Scraping и публикация

| URL | Назначение | Источник |
|---|---|---|
| `/admin/batches` | Партии и выгрузки | `yeezy_scraping` + Rails import API |
| `/admin/suppliers` | Поставщики, альбомы, настройки | `yeezy_scraping` |
| `/admin/scraping` | Запуск и контроль scraping-задач | `yeezy_scraping`, scripts |
| `/admin/measurement-templates` | Библиотека скриншотов и структурированных таблиц замеров для назначения в карточках выгрузки и массового назначения в каталоге | `yeezy_scraping.measurement_templates` |

Целевой поток публикации:

```text
yeezy_scraping batch
  -> AdminYeezy CSV/import adapter
  -> POST /api/v1/admin/import_batches
  -> Rails CRM Postgres
  -> search/media jobs
  -> storefront
```

Подробная инструкция по работе с партиями, CSV-совместимости и атрибутам: [exports.md](./exports.md).

История партий ниже 1024 px отображается карточками с поставщиком, периодом,
количеством, статусом, папкой и раскрываемыми этапами. Переходы к текущему
batch и сохранённым snapshot используют те же canonical URLs; недоступный
исторический snapshot явно помечается и не заменяется текущими товарами.
Редактор batch-товара на mobile открывается полноэкранным sheet, а режим строк
не может заставить телефон показать широкую desktop-таблицу.

## Шаблоны замеров

Оператор загружает скриншот размерной сетки, может распознать его через
настроенный OpenRouter/BYESU AI и проверяет структурированную таблицу перед
сохранением под типом одежды. В карточке товара можно загрузить фото таблицы
прямо из редактора товара: изображение сохраняется в S3-хранилище,
ИИ распознаёт значения, а результат подставляется в `attributes.measurements`.
Если у товара указан исходный поставщик, рядом доступен его сохранённый шаблон;
выбор шаблона также подставляет таблицу и объединяет размеры из строк с текущими
размерами товара. Для фото доступна как загрузка файла, так и вставка изображения
из буфера обмена. В карточке товара
выгрузки видны только шаблоны поставщика этой партии; шаблон применяется явной
кнопкой и заменяет только
`attributes.measurements`: описание, фотографии, видео и другие атрибуты не
изменяются. Удаление шаблона не удаляет уже назначенные таблицы у товаров.
В основном каталоге выбранный шаблон можно назначить сразу отмеченным товарам
через нижнюю панель массовых действий; существующие атрибуты товаров сохраняются,
а размеры шаблона объединяются с уже указанными размерами.

## Фильтры и характеристики

| URL | Назначение | Источник |
|---|---|---|
| `/admin/filter-characteristics` | Реестр атрибутов каталога и их режимов | Rails CRM: `catalog_attribute_definitions`, `catalog_attribute_values` |

В реестре можно отдельно включить показ атрибута в карточке, фильтрацию на сайте и использование как варианта товара. Подписи и алиасы применяются API при построении фасетов, поэтому старые варианты объединяются без массовой перезаписи товаров.

## CRM

| URL | Назначение | Rails API |
|---|---|---|
| `/admin/crm` | CRM с четырьмя вкладками | `/api/v1/admin/*` |
| `/admin/crm/orders` | Список оплачиваемых заказов и шесть статусов | `GET /admin/orders` |
| `/admin/crm/orders/[id]` | Карточка заказа | `GET /admin/orders/:id` |
| `/admin/crm/customers` | Клиенты, фильтр по источнику регистрации и адреса | `GET /admin/customers` |
| `/admin/crm/customers/[id]` | Контакты, адреса и история клиента | `GET /admin/customers/:id` |
| `/admin/crm/telegram` | Telegram-сообщения и рассылки | `GET/POST /admin/store_telegram_*` |
| `/admin/crm/settings` | Получатели уведомлений сайта и Mini App, с отдельными тестами ботов | `GET/POST /admin/telegram_notification_recipients` |

Карточка заказа включает:

- переход только между шестью статусами заказа;
- одно фото товара, название и ссылку, количество, размер и сумму;
- платежи, возвраты, данные клиента, адрес доставки и историю статусов.

Неоплаченные заявки из Mini App и кнопки «сообщить цену» не создают заказов.

На ширине ниже 1024 px CRM dashboard, списки заказов и клиентов используют
карточки с ключевыми полями, статусом/источником и явными ссылками на detail.
Поиск, фильтры и пагинация занимают доступную ширину телефона; detail заказа и
клиента перестраиваются в одну колонку. От 1024 px сохраняются desktop tables
и multi-column detail layout.

## SEO и аналитика

| URL | Назначение | Источник |
|---|---|---|
| `/admin/seo-ai` | AI-каталог: очередь, сравнение, массовая обработка и настройки | Rails SEO AI API + worker (BYESU по умолчанию, также OpenRouter/Cockpit) |
| `/admin/ai-rules` | Глобальные настройки batch AI: OpenRouter/Cockpit, модель, temperature, max tokens и системный промпт китайского каталога | `yeezy_scraping.app_settings` + Cockpit heartbeat |
| `/admin/analytics` | Операционные метрики | AdminYeezy analytics |

SEO landings, redirects, audits и AI-каталог относятся к Rails CRM/API. Production создаёт задания и хранит черновики, а локальный worker забирает их через защищённые `/api/v1/admin/seo_ai/worker/*` endpoints. Прямые записи в CRM-БД запрещены.

## Что важно не сломать

- `AdminYeezy` остается отдельным Next.js приложением.
- Rails CRM - source of truth для каталога, заказов, клиентов, платежей и возвратов.
- `yeezy_scraping` остается технической БД для парсинга, supplier/import batches и AI-процессов.
- NocoDB допустим только для контролируемого просмотра/ограниченной операторской работы, не для прямого CRM workflow.
- Storefront `/admin` не развивается как UI.
