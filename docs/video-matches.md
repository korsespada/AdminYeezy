# Видео → товары

Раздел `/admin/video-matches` привязывает видео поставщика к уже опубликованным
товарам каталога. Он нужен там, где выгрузка состоит из альбомов с видео
(«客订实拍»), а сами товары уже лежат в Rails CRM и пришли другим путём: у
альбомов и товаров нет общих идентификаторов, поэтому пара подбирается по
характеристикам, а решение принимает оператор.

## Данные и границы

- Источник альбомов — партия scraping-БД (`products` + `attributes.szwego_video_url`).
- Товары — опубликованный каталог Rails CRM; чтение и запись только через Rails API
  (`/admin/products`, `/admin/products/:id`). Прямая запись в CRM Postgres запрещена.
- Хранение очереди — таблицы `product_video_matches` и `product_video_match_scope`
  в `yeezy_scraping` (`npm run db:migrate:product-video-matches`).
- Видео переносится в собственный S3 теми же ключами, что и публикация выгрузок:
  `videos/{sha256(source_url)}.mp4` и `videos/{sha256(source_url)}-poster.webp`.
  Ключ детерминирован, поэтому повторный запуск ничего не перекачивает, а
  одинаковые видео из разных альбомов переиспользуют один файл.

## Пресеты

Сценарий целиком описан в `lib/video-match-presets.ts`: бренд каталога, поставщик
scraping-БД, имя поставщика в каталоге, партия выгрузки и список категорий,
которые считаются товарами этого поставщика. Пресет Hermes включает сумки на
плечо, сумки-мессенджеры, тоут, клатчи, кошельки и картхолдеры, косметички,
чемоданы, рюкзаки и поясные сумки.

## Сопоставление

`lib/video-match-fields.ts` разбирает характеристики с двух сторон:

- альбом: `Style：… Colour：… Size：A*B*Ccm Leather：… Hardware：…`;
- каталог: `Стиль: …`, `Цвет: …`, `Размер: …`, `Кожа: …`, `Фурнитура: …`.

Значения нормализуются: регистр, разделители размеров (`*`, `x`, `×`), приставка
«From France», русские и английские названия фурнитуры, порядок слов в модели
(«Kelly Mini 2» = «mini kelly 2»), коды цветов Hermes (`89/Noir` = `89/noir`).

Вес полей: стиль 40, цвет 25, размер 20, кожа 10, фурнитура 5. Уровни:

| Уровень | Балл | Смысл |
| --- | --- | --- |
| `exact` | 100 | совпали все пять характеристик |
| `strong` | 90–99 | совпали модель, цвет и размер, отличается кожа или фурнитура |
| `probable` | 70–89 | модель, цвет и размер совпали частично |
| `weak` | < 70 | в очередь не попадает |

Вариантом товара альбом считается только при совпадении модели и размера
(`isCandidate`). Одинаковые видео схлопываются: у товара остаётся один вариант на
файл, всего до `MAX_CANDIDATES_PER_PRODUCT` (5) вариантов; полное количество
хранится в `candidates_total`.

`product_video_match_scope` фиксирует все просканированные товары, включая те,
для которых вариантов не нашлось (`candidates = 0`) — иначе «нет совпадений»
невозможно отличить от «ещё не считали».

## Рабочий процесс

1. **Закрепить поставщика.** Товары категорий пресета получают
   `primary_supplier_id` поставщика с именем из пресета (Rails создаёт его при
   необходимости). Операция идемпотентна: товары с нужным поставщиком
   пропускаются, повторный запуск продолжает с места остановки.
2. **Собрать совпадения.** Клиент идёт по страницам каталога (по 100 товаров на
   категорию и статус) и после каждой страницы перезаписывает варианты, сохраняя
   уже принятые решения оператора. Архивные товары обрабатываются вторым проходом.
3. **Ревью.** Карточка показывает превью видео альбома и первое фото товара,
   сравнение по пяти характеристикам и переключатель вариантов. Апрув одного
   варианта снимает апрув с остальных вариантов того же товара.
   Массовый апрув работает по выбранным уровням уверенности, отдельной кнопкой —
   только по товарам с единственным вариантом.
4. **Загрузка.** Апрувнутые пары по одной уезжают в S3 и патчат карточку товара
   (`video_url`, `video_poster_url`). Ошибка не теряет пару: строка получает статус
   `failed` с текстом ошибки и может быть возвращена в ожидание.

Статусы строки: `pending` → `approved` → `applied`, либо `rejected` / `failed`.

## Ограничения и известные особенности

- Поставщик публикует несколько альбомов на одну и ту же комбинацию
  характеристик, поэтому «один вариант» — редкость: у большинства товаров 5+
  видео-вариантов с одинаковыми характеристиками. Массовый апрув по уровню
  `exact` берёт самый свежий альбом; визуальная проверка остаётся за оператором.
- 4067 альбомов выгрузки (обувь, сервисные карточки) не содержат блока
  характеристик и в сопоставление не попадают.
- Видео скачивается из источника (xcimg.szwego.com) целиком, перекодируется
  ffmpeg в mp4 ≤ 1080p и получает постер; один файл занимает 5–11 МБ, время
  обработки — около 15 секунд на видео.
- Раздел не публикует товары и не меняет описания, цены и категории.

## Проверки

```powershell
npm run db:migrate:product-video-matches
npx vitest run __tests__/unit/lib/video-match-fields.test.ts
```

Сборка совпадений идемпотентна: повторный запуск на той же выгрузке даёт то же
количество строк, а решения оператора сохраняются.
